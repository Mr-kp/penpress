# R3-1: Vision research spike

## Goal
Make camera-assisted setup trustworthy: from one webcam or phone frame, find the **paper, its borders and orientation, clips/tape (keep-out zones), the bed frame in millimetres, and the pen tip/offset**. The camera is optional for users, so failures must be detected and routed to the manual wizard with a reason, never to silently wrong coordinates.

## Inputs / context to read first
`BRIEF.md` (calibration must-have), R0-1 bed-scene fixtures, `AGENTS.md` section 2.

## Candidate approaches
- Paper quad: classical (adaptive threshold / Canny / contour + polygon approx / Hough), colour-space segmentation, learned segmentation (small U-Net trained on synthetic + real; SAM-class model on T1 for annotation only), hybrid with confidence.
- Metric mapping: ArUco/AprilTag board printed on a sheet or marked on bed (homography, `solvePnP` with intrinsics), vs markerless from known bed size + corners; lens distortion estimation (checkerboard) for wide-angle webcams.
- Clips/tape/obstacles: colour+edge segmentation, morphological analysis along the paper border, learned.
- Pen tip and offset: print a calibration dot/cross with the pen, detect it in the image, compute (dx, dy) from nozzle/home reference; plus a **hover test** protocol.
- Z-contact: investigate whether any camera view (side view, phone propped at the front) can verify contact; otherwise define a non-camera step-and-check routine (R5-1 owns the physics).
- Phone-as-camera: browser `getUserMedia` over a **private** HTTPS endpoint (`tailscale serve`, never funnel) or QR-code pairing; measure latency/resolution tradeoffs.
- Plot verification: after plotting a test pattern, photograph it and measure position error and line presence.

## Deliverables
1. `docs/developer/research/R3-1.md`: evidence log, comparison of methods.
2. `research/R3-1/` prototypes with a CLI: `detect-paper`, `detect-clips`, `calibrate-homography`, `find-pen-offset`, `verify-plot`, each emitting JSON with confidence and failure reason.
3. Benchmark on R0-1 synthetic scenes (>= 300 scenes across lighting/pose/lens presets) and the real-image set; per-condition breakdown.
4. Failure taxonomy: which conditions break detection (glare, dark paper, shadow, partial occlusion, extreme angle) and how the system detects its own failure.
5. ADR `docs/developer/adr/0003-vision-calibration.md`. Also a **camera placement guide** draft for the user (angle, distance, lighting, marker placement) derived from the measured error vs pose curves.
6. A synthetic-to-real gap check: run the detector on the real internet images and report the error vs the manual annotation.

## Metrics
| Metric | Target |
|---|---|
| Paper corner error, synthetic, top-down | mean <= 0.7 mm, p95 <= 1.5 mm |
| Paper corner error, synthetic, oblique 15-40 deg with markers | mean <= 1.0 mm, p95 <= 2.0 mm |
| Detection success (corner error < 3 mm) over all non-negative scenes | >= 95% |
| False accept on negative scenes (missing corner, no paper, glare) | <= 2%: they must be flagged low-confidence or failed |
| Clip/tape detection recall at the border | >= 90%, precision >= 90% |
| Pen offset estimate error vs ground truth | <= 0.5 mm |
| Real-image quad IoU vs manual annotation | median >= 0.95 |
| Speed on T0 CPU, 1280x720 frame | <= 1.0 s |

## Acceptance
- Benchmark reproducible from README within +-3%; per-condition tables included, failures shown with images.
- Confidence calibration: plot confidence vs actual error; show that a threshold exists that rejects >= 95% of wrong results.
- Prototype never returns coordinates without a confidence + validity flag.
- ADR accepted with decision, numbers, fallbacks (manual wizard rules), and dependencies with licences.
- Real-image results presented honestly (annotate 3 worst results).

## Anti-shortcut
- Do not tune thresholds on the evaluation scenes; split generation seeds into tune/test.
- Do not report only successes. Failures with images go in the evidence.
- Do not treat synthetic success as proof for real cameras: report the gap.
- Do not require markers for the default path unless the numbers justify it; explain the tradeoff.
