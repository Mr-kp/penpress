# R1-1: Handwriting cloning research spike

## Goal
Decide, with measurements, how PenPress turns the user's handwriting sample into strokes for **arbitrary new text**, readable and recognisably theirs, running locally. Also decide what the quality ceiling is and how the UI should guide the user to hit it.

Key insight to respect: a plotter needs **online strokes** (ordered pen paths), but a photo gives only pixels. Every approach must bridge that gap, or the user must provide online data (phone/tablet canvas capture gives x, y, time, pressure: the best input).

## Inputs / context to read first
`docs/developer/research/verified-landscape.md` (candidates + licences), `AGENTS.md` section 2 (research protocol), fixtures from R0-1.

## Candidate approaches (seed list, extend freely)
A. **Glyph bank**: sample sheet -> segment cells -> skeletonize (skimage, `LingDong-/skeleton-tracing`) -> ordered strokes -> spline fit -> multi-variant bank + ligature/connection rules + humanizer. Deterministic, always readable, limited naturalness for cursive.
B. **SDT (`dailenson/SDT`)** online style-disentangled Transformer: style from reference strokes, content from text; plotter-native.
C. **Graves RNN** (`X-rayLaser/pytorch-handwriting-synthesis-toolkit`, MIT): style priming with a short online sample.
D. **One-DM / DiffusionPen** raster diffusion -> skeleton -> stroke order recovery.
E. **Stroke recovery for offline photo -> online strokes** (skeleton graph traversal with writing-order heuristics; optionally learned) to feed B/C from photos.
F. **Hybrid**: glyph bank for guaranteed legibility + neural model for connection/flow, chosen by a quality gate per word.
G. Opt-in cloud VLM agent (HandwritingAgent-style): only needs a prototype to measure, product-optional.
H. **Phone/tablet canvas capture** of the sample (pointer events -> online strokes): design the capture protocol and compare quality against photo input.

## Deliverables
1. `docs/developer/research/R1-1.md`: evidence log (verified licences with dates, what you ran, what broke).
2. `research/R1-1/` runnable prototypes for at least **three** approaches (A is mandatory plus two others), a common `Synthesizer` protocol sketch (input: profile + text; output: list of strokes in mm with pen-up gaps), and a benchmark script.
3. Benchmark results `research/R1-1/results/*.csv` + rendered images + a short writeup table.
4. ADR `docs/developer/adr/0001-handwriting-cloning.md` (template in `adr/0000-template.md`).
5. Sample-collection UX proposal (what to ask the user to write, how many samples, phone capture flow) with measured quality-vs-effort curve (quality when given 1, 3, 5 sheets / n words).
6. If any neural weights are needed: Colab notebook(s) in `notebooks/`, manifest rows in `models/MANIFEST.md`, T0 CPU timing.

## Metrics (all on R0-1 fixtures; also run on the user's real sample when available)
| Metric | How | Initial target |
|---|---|---|
| Legibility | Render strokes -> OCR (Tesseract and a local HTR model, e.g. TrOCR if CPU-feasible) -> character error rate on 30 test sentences not in the sample | CER <= 8% (print-like), <= 15% (cursive) |
| Style fidelity | slant, x-height ratio, stroke curvature stats, spacing; plus Handwriting Distance if implementable | within 15% of the sample's measured stats |
| Variation | same letter 20x -> number of distinct shapes (cluster at fixed tolerance) | >= 4 clusters per common letter |
| Plottability | strokes per char, total path length per line, number of pen lifts, self-intersection, max curvature vs printer limits | no zero-length or NaN strokes; pen lifts per word <= 2 for print style |
| Speed (T0 CPU) | seconds per 100 words after profile build | <= 60 s, or precomputed bank makes it instant |
| Profile build time | seconds from photo to usable profile | <= 5 min on T0 or clearly offloaded to T1 with caching |
| Licence | all code and weights shippable under permissive terms | required |

Thresholds can be changed only through the ADR with a justification.

## Acceptance
- `research/R1-1/README.md` gives copy-paste commands; a reviewer reproduces the benchmark table within +-5% on T0.
- At least 3 approaches measured on the **same** fixtures and metrics, failures included.
- ADR accepted: chosen approach (or hybrid), numbers, fallback, and the exact list of repos/papers/weights to be vendored or depended on with licence verdicts.
- Stroke-recovery quality measured against R0-1 online ground truth (mean Chamfer distance in px, stroke-count error, order accuracy).
- A rendered page (image) of >= 5 sentences in the cloned style that you have opened and described honestly (flaws included).
- Statement of the **quality ceiling** and the top 3 risks, with a mitigation each.

## Anti-shortcut
- Do not conclude from papers/READMEs. Run the code.
- Do not evaluate only on training-set styles of the pretrained model.
- Do not pick a model whose licence you did not verify.
- Do not hand-tune on the test sentences. Hold them out.
- Do not hide failures: include the worst 10 words rendered.
- Do not recommend something that needs a GPU at runtime without a CPU plan.
